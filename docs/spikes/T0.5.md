## Hành vi quan sát được

| Thao tác | Kết quả | Chạy lại lần 2 |
| --- | --- | --- |
| `addSubIssue` A←B, B←C (3 cấp) | OK; đọc lại REST `sub_issues` của A = `[2]`; B: `parent #1`, `subIssuesSummary.total=1` | **Lỗi** VALIDATION: "Issue may not contain duplicate sub-issues and Sub issue may only have one parent" |
| `addBlockedBy` B bị D chặn | OK; `blockedBy` của B = `[4]` | **Lỗi** VALIDATION: "Target issue has already been taken" |
| `updateIssueIssueType` A → `Feature` (type có sẵn của org) | OK, `issueType.name = Feature` | — |
| `addProjectV2ItemById` #1–#4 | OK, 4 item | **Idempotent**: trả về đúng item id cũ, tổng vẫn 4 |
| `createProjectV2Field` SINGLE_SELECT `Priority` P0–P3 | OK, có option id | **Lỗi** UNPROCESSABLE: "Name has already been taken" |
| `createProjectV2Field` ITERATION `Sprint` (14 ngày) | OK, `iterations: []` (chưa có iteration nào được sinh) | — |
| `updateProjectV2ItemFieldValue` Priority=P0 trên #1 | OK; đọc lại `fieldValueByName = P0` | — |
| `createProjectV2View` TABLE/BOARD/ROADMAP | OK, view #2/#3/#4 | **Tạo bản trùng** (view #5 cùng tên) — đã xóa bằng `deleteProjectV2View` |
| `createIssueType` "Spike" (cấp org) | **Chưa test**: lệnh bị bộ phân loại quyền chặn ("Destructive or Unwanted Actions") vì thay đổi cấu hình toàn org, vượt phạm vi được cho phép | — |

## Giới hạn

- `ProjectV2ViewConfigurationInput` chỉ có `visibleFieldIds`: **không đặt được filter/group/sort/layout field của view qua API** → WBS/Sprint Board/Review&QA cần hướng dẫn cấu hình thủ công phần filter/group.
- Field ITERATION tạo với `iterations: []`; chưa kiểm tra việc tự sinh iteration hay thêm iteration qua `updateProjectV2Field`.
- Chưa test độ sâu 6–8 cấp, giới hạn 100 con, sub-issue liên repo, dependency liên repo.
- 13 Issue Type của OMI cần org owner tạo (`createIssueType`); tài khoản là member.

## Khuyến nghị

- Mọi thao tác GitHub trong runtime theo mẫu **read → diff → write** (desired state), vì API trả lỗi khi trùng (sub-issue, dependency, field) hoặc âm thầm tạo trùng (view).
- Dùng Issue Type có sẵn (`Task/Bug/Feature`) + label `type:<OMI type>` cho các type còn lại, trừ khi org owner phê duyệt tạo type mới.
- View: tạo bằng API (tên + layout), filter/group cấu hình thủ công theo hướng dẫn sinh tự động.

## Fallback

Label `type:*` cho Issue Type; hướng dẫn thủ công cho cấu hình view; chỉ dùng thao tác field mà API hỗ trợ.
