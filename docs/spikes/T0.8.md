# T0.8 — Tính idempotent của resume, outbox comment và cleanup sau squash merge

**Quyết định:** **GO** — (1) cleanup git cục bộ idempotent khi tiêm crash; (2) reconcile comment theo marker trên GitHub thật cho đúng 1 comment sau crash; (3) cleanup dựa trên merge receipt squash thật hoạt động an toàn không cần `--force`. Native workflow replay: không áp dụng (xem T0.1).
Git `2.55.0.windows.5`, gh `2.100.0`, 2026-11-17.

## Phần A — Cleanup git cục bộ (fixture bare repo)

### Thiết lập (A)

Fixture cục bộ từ [T0.3](T0.3.md): `origin.git` bare, clone `repo`, worktree `101` (`feature/101-a`) và `102` (`feature/102-b`) từ `origin/develop` (`1bc0d5b`), marker `.omi-owner.json` (untracked). Squash merge mô phỏng bằng clone thứ hai `git merge --squash` vào `develop`.

### Quy trình (bash chỉ dùng cho spike)

```bash
cleanup() {  # $1=after-worktree để tiêm crash
  if worktree còn trong `git worktree list --porcelain`; then
    lưu trữ + xóa .omi-owner.json; yêu cầu `git -C $W status --porcelain` rỗng, nếu không CLEANUP_FAILED
    git worktree remove "$W"            # không --force
  else bỏ qua; fi
  [điểm tiêm crash]
  if branch còn; then
    yêu cầu tip cục bộ == PR head trong receipt, nếu không CLEANUP_FAILED
    git branch -D <branch>
  else bỏ qua; fi
  git worktree prune -v
}
```

### Quan sát (A)

| Bước | Kết quả |
| --- | --- |
| `git branch --merged origin/develop` sau squash | `feature/101-a` đã squash **KHÔNG** có; `feature/102-b` chưa đụng tới **LẠI có** (0 commit ⇒ "merged" giả) |
| `git branch -d feature/101-a` | từ chối: `used by worktree` |
| `git worktree remove` (không force) khi có marker untracked | `fatal: ... contains modified or untracked files, use --force` (exit 128) |
| Cleanup khi có file tracked bị sửa | `CLEANUP_FAILED: dirty worktree`, không xóa gì |
| Lần 1, crash sau khi xóa worktree | worktree đã xóa, branch còn (rc=2) |
| Lần 2 replay | bỏ qua worktree → xóa branch (tip `da5640b` khớp) → prune (rc=0) |
| Lần 3 replay | mọi bước bỏ qua (rc=0); worktree 102 không bị đụng |

## Phần B — Outbox comment với marker (GitHub thật)

### Thiết lập (B)

Script probe `t08-outbox.mjs` (scratchpad, ~25 dòng Node, chỉ dùng `gh api`): marker `<!-- omi:run=spike-t08;step=code-review;round=1;attempt=1 -->`; file JSON đóng vai bản ghi outbox SQLite lưu `commentId`. Thuật toán: nếu chưa có id → liệt kê comment (paginate) tìm marker → có thì PATCH, không thì POST; tham số `crash=1` thoát trước khi lưu id. Issue #2 của `omi-home/omi-spike-p0-20261117`.

### Quan sát (B)

| Bước | Kết quả | Số comment có marker |
| --- | --- | --- |
| Lần 1: POST rồi crash trước khi lưu id | `POST 6939698713`, `!! injected crash` (rc=2) | 1 |
| Replay có id đã lưu (2 lần) | `PATCH 6939698713` | 1 |
| Xóa store (mô phỏng mất id sau crash) → chạy lại | `reconciled existing comment 6939698713` → `PATCH` → lưu id | **1** |
| Nội dung cuối | `Status: FAILED-RETRY` (bản cập nhật cuối cùng) | 1 |

Ghi chú trung thực: lần replay đầu tiên ngay sau crash đã chạy nhưng output bị cắt (lỗi ở lệnh đếm phụ, `--slurp` không dùng chung với `--jq`), nên nhánh reconcile được chứng minh bằng lần chạy riêng sau khi xóa store.

## Phần C — Cleanup bằng merge receipt squash thật

```bash
git -c credential.helper= -c 'credential.helper=!gh auth git-credential' clone https://github.com/omi-home/omi-spike-p0-20261117.git repo
git worktree add .omi-worktrees/5 -b feature/5-t06 origin/feature/5-t06
gh pr view 6 --json state,mergedAt,baseRefName,headRefName,headRefOid,closingIssuesReferences
# xóa chỉ khi: merged && base==develop && head==feature/5-t06 && issues∋5 && headRefOid==tip cục bộ==tip remote && worktree sạch
```

| Kiểm tra | Kết quả |
| --- | --- |
| `git branch --merged origin/develop` chứa `feature/5-t06` | **0** (squash) |
| Receipt PR #6 | `merged: true`, `base: develop`, `head: feature/5-t06`, `headRefOid: ac039b3…`, `issues: [5]` |
| Tip cục bộ / remote | `ac039b3…` / `ac039b3…` (khớp) |
| Cleanup | `git worktree remove` (không force) → `Deleted branch feature/5-t06 (was ac039b3)` → `CLEANUP OK` |
| Branch remote | **vẫn còn** (cố ý không xóa; do policy/quyền quyết định) |

## Giới hạn

- Outbox chỉ có 1 tiến trình; chưa test hai runner chạy đồng thời (race giữa list và POST) — cần lease/lock trong SQLite.
- Tìm marker bằng cách liệt kê toàn bộ comment: chi phí tăng theo số comment; chưa test rate limit/429.
- Comment bị người dùng sửa xóa mất marker sẽ không reconcile được (sẽ POST bản mới).
- Chưa test cleanup tiến trình/container, merge kiểu rebase, crash giữa lúc merge và lúc ghi receipt.

## Khuyến nghị

1. Không bao giờ dùng `git branch --merged` làm bằng chứng merge. Bằng chứng = receipt GitHub: `merged`, base, head, `headRefOid` == tip cục bộ == tip remote, Issue chính.
2. Mỗi bước cleanup là kiểm-tra-rồi-làm trên trạng thái quan sát được → replay an toàn.
3. Outbox: lưu bản ghi pending **trước** khi gọi API; khi thiếu `commentId` luôn tìm marker trước khi POST; marker key = `repo+issue+run+step+round+attempt`.
4. Marker sở hữu worktree đặt trong `.git/info/exclude` hoặc ngoài cây; không `--force`; không tự xóa branch remote.

## Fallback

Nếu reconcile marker không đáng tin (comment bị sửa, rate limit): chặn dispatch bước tiếp theo, đánh dấu `RECOVERY_REQUIRED` và yêu cầu reconcile thủ công.
