# T0.1 — Native workflow gọi plugin agent có tên, và model/effort

**Quyết định (chạy lại sau khi bật Dynamic workflows):** **GO có giới hạn** cho native workflow làm *adapter điều phối*: workflow gọi được **plugin agent có tên** (`agentType`), override `model` có hiệu lực và quan sát được, skill preload hoạt động. **Không dùng** cho phần việc cần worktree do OMI sở hữu (không có option `cwd`; `isolation: 'worktree'` tạo worktree ngoài quản lý) và **effort không quan sát được**. MVP vẫn giữ **gọi agent trực tiếp + OMI CLI FSM** làm đường chính; workflow là adapter tùy chọn cho các bước không ghi file (review, phân tích).
Claude Code `2.1.325`, Windows 11, 2026-11-17.

## Lịch sử

| Lần chạy | Kết quả |
| --- | --- |
| 1 (trước khi bật) | Không có tool `Workflow` trong `init.tools`; `/workflow-authoring` → `Unknown skill` → NO-GO native, GO fallback |
| 2 (sau khi người dùng bật "Dynamic workflows" trong `/config`) | `~/.claude/settings.json` có `"enableWorkflows": true`; tool `Workflow`, `/workflow-authoring`, `/deep-research` xuất hiện |

## Thiết lập

Plugin dùng một lần `omi-spike` (nạp bằng `--plugin-dir`):

```text
omi-spike-plugin/.claude-plugin/plugin.json   {"name":"omi-spike","version":"0.0.1","description":"Disposable Phase 0 fixture"}
omi-spike-plugin/agents/spike-backend.md      model: haiku (lần 2), effort: low, disallowedTools: Skill, skills: [spike-specialist]
omi-spike-plugin/skills/spike-specialist/SKILL.md   body: "SPECIALIST-BODY-CANARY-7F3A ..."
omi-spike-plugin/skills/spike-entry/SKILL.md        body: "ENTRY-BODY-CANARY-19C2 ..."
omi-spike-plugin/workflows/t01.js             plugin workflow → chạy bằng /omi-spike:t01
```

API `agent()` lấy từ skill `/workflow-authoring` đi kèm bản cài (không suy đoán):

```text
agent(prompt, {label?, phase?, schema?, model?, effort?, isolation?: 'worktree', agentType?}) — không có option cwd
Script: không có filesystem/Node API; Date.now()/Math.random()/new Date() ném lỗi; không import()
```

`workflows/t01.js` (rút gọn):

```javascript
export const meta = { name: 't01', description: 'OMI T0.1 spike: named plugin agent via native workflow ...', phases: [{ title: 'Probe' }] }
const [plain, override, iso] = await parallel([
  () => agent(CTX + NOSHELL, { label: 'agentType only', schema: REPORT, agentType: 'omi-spike:spike-backend' }),
  () => agent(CTX + NOSHELL, { label: 'agentType + model opus + effort low', schema: REPORT, agentType: 'omi-spike:spike-backend', model: 'opus', effort: 'low' }),
  () => agent(CTX + SHELL,   { label: 'agentType + isolation worktree', schema: REPORT, agentType: 'omi-spike:spike-backend', isolation: 'worktree' }),
])
return { runtime: { process: typeof process, require: typeof require, fetch: typeof fetch }, plain, override, iso }
```

## Giới hạn

- **Không có `cwd`** cho `agent()`: agent chạy ở cwd của phiên (hoặc worktree tự tạo) → không trỏ được vào worktree do OMI sở hữu, trừ khi dặn qua prompt + đường dẫn tuyệt đối (giống T0.3 cách B, có vướng quyền).
- `isolation: 'worktree'` tạo worktree **ngoài quản lý** dưới `.claude/worktrees/`, branch `worktree-wf_*` từ HEAD, bị `locked`, không tự xóa khi có thay đổi → vi phạm quy tắc "một Issue – một branch/worktree do OMI sở hữu, từ `origin/develop`". Không dùng.
- Script không có shell/filesystem → không gọi được `omi` CLI từ script; muốn gọi CLI phải thông qua một agent (tốn LLM call, trái nguyên tắc script-first).
- Resume native chạy lại từ agent đầu tiên có prompt thay đổi trở đi → không dùng làm nguồn sự thật cho side effect; OMI SQLite vẫn là authoritative.
- Workflow phụ thuộc cấu hình user (`enableWorkflows`); máy khác/CI không bật thì không có → không được là đường bắt buộc.
- Trường `pickedEffortModel` trong `meta.json` luôn là `claude-sonnet-5-5`, kể cả agent chạy Haiku → ý nghĩa không rõ, không dùng làm `actualModel`.

## Khuyến nghị

1. Đường chính MVP: OMI CLI khởi chạy agent có tên bằng tiến trình riêng (`claude -p --agent <plugin>:<role>`, cwd = worktree OMI) — như T0.3 cách A.
2. Native workflow là **adapter tùy chọn** cho các bước *chỉ đọc* chạy song song (ví dụ code review đa chiều, adversarial verify), dùng `agentType` + `schema`; OMI CLI nhận kết quả và tự publish comment/chuyển trạng thái.
3. Ghi `requestedModel`/`requestedEffort` từ policy; `actualModel` từ `modelUsage`/`message.model`; `actualEffort: unknown`.
4. `omi doctor` kiểm tra `Workflow` khả dụng; nếu không → tắt adapter workflow, không lỗi.
5. Cấm `isolation: 'worktree'` trong mọi workflow của OMI (có thể kiểm tra tĩnh khi validate plugin).

## Fallback

Nếu adapter workflow không khả dụng hoặc không đáng tin: Coordinator/CLI gọi trực tiếp agent có tên (đã xác minh ở lần 1 và T0.3). Fixture còn để lại worktree `repo/.claude/worktrees/wf_9c37f990-2cf-3` (locked) trong scratchpad làm bằng chứng.
