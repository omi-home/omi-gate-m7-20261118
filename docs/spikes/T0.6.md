# T0.6 — Liên kết PR ↔ Issue và hành vi đóng issue khi `develop` là mặc định

**Quyết định:** **GO có điều kiện** — native auto-close và `closingIssuesReferences` **chỉ hoạt động khi base của PR là default branch**. Nếu dùng native linking thì `develop` phải là default branch (cần PO phê duyệt trên repo thật); nếu không, dùng fallback liên kết do OMI quản lý.
Repo `omi-home/omi-spike-p0-20261117` (public), 2026-11-17.

## Thiết lập

Mỗi trường hợp: tạo issue → tạo branch `feature/<N>-t06` từ `develop` (git refs API) → thêm 1 file (contents API) → PR `-B develop` với body `Closes #<N>` → squash merge.

## Lệnh thực tế

```bash
gh repo edit omi-home/omi-spike-p0-20261117 --default-branch develop   # rồi main cho trường hợp 2
gh issue create -R <repo> -t "T0.6 <case> issue" -b fixture
gh api repos/<repo>/git/refs -f ref=refs/heads/feature/<N>-t06 -f sha=<develop sha>
gh api -X PUT repos/<repo>/contents/t06-<N>.txt -f branch=feature/<N>-t06 -f message=... -f content=<base64>
gh pr create -R <repo> -B develop -H feature/<N>-t06 -t "T0.6 <case>" -b "Closes #<N>"
gh api graphql -f query='{repository(owner:"omi-home",name:"omi-spike-p0-20261117"){pullRequest(number:<P>){baseRefName closingIssuesReferences(first:5){nodes{number}}}}}'
gh pr merge <P> -R <repo> --squash
gh pr view <P> --json state,mergedAt,headRefOid,mergeCommit
gh issue view <N> --json state,stateReason,closedByPullRequestsReferences
```

## Giới hạn

- `closingIssuesReferences` được điền **bất đồng bộ** (≤ ~15 giây trong lần test); đọc ngay sau khi tạo PR sẽ thấy rỗng → validator phải retry có backoff.
- Khi base ≠ default branch, GitHub **không ghi nhận** liên kết closing nào → không thể dùng `closingIssuesReferences` để xác thực Issue chính.
- Chưa test: liên kết thủ công "Development" trên UI, `createLinkedBranch`, merge kiểu rebase/merge commit, PR release `develop → main`.
- Repo fixture hiện để `develop` là default (sau trường hợp 3).

## Khuyến nghị

1. Khuyến nghị đặt `develop` làm default branch (cần PO phê duyệt trên repo thật) để dùng native closing + `closingIssuesReferences`.
2. Validator PR: kiểm tra base, head, rồi poll `closingIssuesReferences` (backoff, timeout) cho tới khi chứa đúng một Issue chính.
3. Không dựa vào auto-close để coi là Done: CLI vẫn đóng/chuyển trạng thái Issue sau DoD.

## Fallback

Khi `develop` không phải default: OMI ghi Issue chính trong body PR (marker có cấu trúc) + bản ghi SQLite `PR ↔ Issue`, xác thực bằng dữ liệu đó, và CLI đóng Issue tường minh sau khi merge receipt + DoD đạt.
